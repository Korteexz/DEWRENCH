# Visão do produto

DEWRENCH quer tornar sistemas invisíveis e textuais observáveis, manipuláveis e compreensíveis sem substituir as ferramentas reais.

## Problema

Desenvolvedores alternam entre terminal, GUIs, dashboards e documentação para entender causalidade. Interfaces simples demais escondem o mecanismo; interfaces completas demais viram painéis densos sem narrativa.

## Proposta

Uma bancada desktop modular em que cada ferramenta fornece dados e operações, enquanto o DEWRENCH oferece modelos visuais coerentes:

- Git → histórico, branches, staging e remotes;
- RRF → caminho de request/response destacado em tempo real;
- Docker/Kubernetes → topologia e estado de serviços;
- database → relações, dados e alterações;
- CI/CD → pipeline e causalidade;
- Terraform → plano, recursos e impacto.

## Diferencial

Não existe uma visualização universal. O mesmo estado poderá ser visto como grafo, fluxograma, blocos, tabela ou log, mantendo o mesmo modelo interno.

## Filosofia

- local-first;
- open source;
- multiplataforma;
- modular e incrementável;
- visual sem mistificação;
- seguro por consequência;
- amigável para aprender, poderoso para operar;
- IA opcional.

## Não objetivos

- reimplementar Git/Docker/Kubernetes;
- substituir IDEs completas no curto prazo;
- depender de cloud para tarefas locais;
- esconder conceitos técnicos para parecer simples;
- prometer todos os módulos antes de um vertical slice funcional.
